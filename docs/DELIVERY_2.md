## A. `gen2` — закрытие 16 отбраковок

### A1. `shafts` — 15 отбраковок «not watertight; 129 components»

Причина: корпус вала строился через `rotate_extrude()` по замкнутому профилю,
у которого часть точек лежала на оси, и у 15 валов без логических операций
эта вырожденная сетка уходила в STL как есть. У остальных 65 валов булева
операция заставляла manifold починить сетку — поэтому падали не все.

Что изменено в `tools/dataset_gen2/families/profiles.py`:

- корпус — стек цилиндров, каждая меньшая ступень утоплена в большую на 0.4 мм
  (положительное перекрытие, никаких касаний нулевой площади);
- фаски торцов и канавка под стопорное кольцо — кольцевые вырезы
  `rotate_extrude()`, профиль которых остаётся не ближе 1.2 мм к оси;
- каждый режущий элемент проходит тело насквозь с перебегом 2.5 мм с каждой
  открытой стороны (было 0.5 мм — именно такие «нулевые» клинья и давали
  шероховатую сетку);
- отверстие под поперечный штифт оставляет вокруг себя ≥ 4 мм материала;
- шпоночный паз действительно фрезеруется в первой ступени (раньше он молча
  не срезал ничего: был привязан к радиусу самой большой ступени).

### A2. `lbrackets/part_0062` — «3 components»

Причина: косынка касалась полок по касательной, а торцы отверстий/пазов
заканчивались в 0.5 мм от наклонной грани, что давало две клиновидные плёнки
нулевой площади.

Что изменено в `tools/dataset_gen2/families/brackets.py`:

- косынка утоплена в обе полки на 1.6 мм (было 0.9 мм, то есть «почти
  касание» на наклонной грани);
- все вырезы под отверстия и пазы получили перебег 2.5 мм;
- отверстие поджимного винта Z-кронштейна перенесено в свободный пролёт
  перемычки; если перемычка слишком короткая, отверстие не рисуется, а
  промпт говорит про два отверстия;
- косынка Z-кронштейна больше не дотягивается до нижнего крепёжного отверстия.

### A3. Новый локальный контроль под приёмника (без CLI)

`tools/dataset_gen2/stlcheck.py` собирает manifold, пишет бинарный STL с
80-байтовым заголовком (как OpenSCAD), затем повторяет ваши вызовы:
`trimesh.load(..., force="mesh", process=True)`, `split()`, `is_watertight`
и дополнительно считает треугольники нулевой площади. Именно этот контроль
нашёл обе причины отбраковок. Он подключён к:

- `tools/dataset_gen2/verify_corpus.py --parts-dir <dir> --stl` — независимый
  аудит файлов на диске;
- `tools/dataset_gen2/build_corpus.py --stl-audit` и отчёту
  `GENERATION_REPORT.md`.

Текущее состояние `gen2` (пересобран целиком, манифест пересчитан):
`manifest.jsonl` sha256 `d8039c72763db9582d1e8b2c3fb8413801d1be01bf92191e6fea67af34a8788f`,
2240/28, 0 отбраковок при генерации, STL-контроль 2240 из 2240 чистый,
максимальное расхождение габаритов с манифестом 2.42 % (порог 15 %).

> Проверить причину «129 components» окончательно может только ваш прогон

### Как проверялся `gen3` (без CLI)

1. Внутри генератора каждый образец проходит `check_part` (заголовок `$fn = 32;`,
   запрещённые конструкции, ≤ 12 КБ, один компонент, ненулевой объём,
   перекрытие/зазоры, связность графа), проверку 5–250 мм по каждой оси и
   STL-контроль из A3. Из 2600 записей одна была отброшена и заменена
   (`herringbones` индекс 80: `watertight False, 5 components, 8 degenerate`),
   110 повторных наборов параметров пропущены как байтовые дубликаты.
2. `python tools/dataset_gen2/verify_corpus.py --parts-dir optional_data/data/gen3`
   → 2600 строк / 26 семейств / 400 графов, максимальное расхождение габаритов
   **1.69 %** (порог 15 %), список SHA-256 совпал, проблем нет.
3. `GENERATION_REPORT.md` дополнительно содержит строку про STL-прогон всех
   2600 образцов: 0 не-watertight, 0 многокомпонентных, 0 вырожденных.
4. `tools/dataset_gen3/check_voids.py` — отдельная проверка, что полости
   действительно прорезаны: 45 проб в 9 семействах (крышка, барашек, венец,
   шеврон, червячное колесо, ролик, кулачок, хомут, крестовина) — во всех
   случаях точка на оси внутри пустоты, то есть «глухих» отверстий нет.

## C. Что запустить для проверки

```bash
# 1. статические + геометрические инварианты обоих корпусов (без OpenSCAD)
python tools/dataset_gen2/verify_corpus.py --parts-dir optional_data/data/gen2
python tools/dataset_gen2/verify_corpus.py --parts-dir optional_data/data/gen3

# 2. тот же аудит плюс STL-прогон (вода/компоненты/вырожденные) — медленно
python tools/dataset_gen2/verify_corpus.py --parts-dir optional_data/data/gen3 --stl

# 3. полости действительно прорезаны
python tools/dataset_gen3/check_voids.py --parts-dir optional_data/data/gen3

# 4. контрольные суммы
cd optional_data/data/gen3 && sha256sum -c SHA256SUMS.txt
cd ../gen2 && sha256sum -c SHA256SUMS.txt

# 5. ваша сторона: настоящий OpenSCAD
openscad --backend=manifold -o /tmp/out.stl optional_data/data/gen3/threads/part_0001.scad
openscad --backend=manifold -o /tmp/out.stl optional_data/data/gen2/shafts/part_0001.scad

# 6. пересборка (детерминированная: Rng(family, index), seed 20260929)
python tools/dataset_gen3/build3.py --count 100 --out optional_data/data/gen3 --report
python tools/dataset_gen2/build_corpus.py --count 80 --report
```

## D. Честные ограничения

- Резьба — приближённая: кольцевые выступы/спираль через `rotate_extrude`
  с шагом, а не точный ISO-профиль (в заявке это допускалось).
- Эвольвента в зубчатых венцах — полигональная аппроксимация с шагом цикла.
- Кулачки, рычаги, крюки, ролики построены полигонами и `rotate_extrude` —
  без интерактивного профиля (это задел под будущий SketchCanvas, как и
  просили в заявке).
- `livinghinges` держит перемычку 0.9–1.4 мм (требование ≥ 0.8 мм выполнено).
- Локальный STL-контроль — симуляция приёмника на `manifold` + `trimesh`;
  окончательное слово за вашим прогоном `openscad --backend=manifold`.

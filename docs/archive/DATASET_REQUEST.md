# Заявка на генерацию датасета (для внешнего агента)

> Контекст: мы обучаем модель писать код OpenSCAD по текстовому описанию детали.
> Существующий корпус шаблонный (~6 семейств), модель его меморизирует.
> Нужен **разнообразный** корпус «как из реальной мастерской». Ниже — жёсткий
> контракт. Наша сторона прогонит всё через настоящий OpenSCAD (manifold) и
> отсеет невалидное математически: watertight, одна компонента, габариты
> в допуске 15%, Эйлерова характеристика согласована.

## Формат сдачи (обязательно)

Каталог в репозитории: `optional_data/data/gen2/`

```
gen2/
├── manifest.jsonl          # одна строка = один образец
├── <family>/part_0001.scad # текстовый файл OpenSCAD на образец
├── <family>/part_0002.scad
└── ...
```

Строка manifest.jsonl (JSON, UTF-8):

```json
{
  "file": "brackets/part_0001.scad",
  "family": "brackets",
  "prompt_ru": "Уголок крепёжный 40x40x20 мм, толщина 4 мм, 2 отверстия под М4",
  "prompt_en": "L-bracket 40x40x20 mm, 4 mm wall, two M4 holes",
  "expected_bbox_mm": [40.0, 40.0, 20.0],
  "parameters": {"width": 40, "height": 40, "depth": 20, "wall": 4, "hole_d": 4.3},
  "graph": null
}
```

- `family` — латиницей, одно слово (имя подкаталога).
- `prompt_ru` **и** `prompt_en` — обязательно оба; формулировки НЕ шаблонные
  (см. «Язык»).
- `expected_bbox_mm` — габариты по XYZ в мм (внешний прямоугольник детали).
- `graph` — только для ферменных образцов (см. ниже): узлы в мм и рёбра
  индексами. Иначе `null`.

## Жёсткие правила кода

1. Первая строка каждого .scad: `$fn = 32;`
2. Полностью параметрически: размеры — переменными в шапке файла. На вход
   модели потом ляжет именно такой стиль — код, который учит «магические числа»,
   засоряет обучение.
3. **Никаких точных касаний.** Детали, соприкасающиеся нулевой площадью
   (сфера, вписанная в цилиндр; касательные плоскости) — запрещены: бэкенд
   manifold недетерминирован на них. Любое соединение — с положительным
   перекрытием (≥ 0.2 мм внутрь) или положительным зазором.
4. Одна связная твёрдая деталь на файл. Никаких «висящих» элементов.
5. Самодостаточность: запрещены `import()`, `surface()`, чтение внешних
   файлов, `text()` (шрифты не переносимы), `children()`, `let` с рекурсией
   без ограничения глубины. Без `echo`-мусора в stdout.
6. Реальные размеры: 5–250 мм по любой оси. Толщины стенок ≥ 1.2 мм
   (печатабельность — часть <<вкуса>> датасета).
7. Полный файл ≤ 4000 токенов (~12 КБ текста) — без километровых
   `polyhedron`-таблиц; если формула грани нужна — генерируйте циклом.
8. Код обязан быть детерминированным: никаких `rands()` без фиксированного
   seed и тому подобного.

## Покрытие семейств (двигайтесь по списку; ≥ 40 образцов на семейство)

**Твердотелые (CSG, раздел «voxel»):**
- кронштейны L/U/Z-образные с евро-отверстиями и потайки
- платы-переходники моторов (NEMA 17/23/34) с обводами
- корпуса с крышками: ниппели, ушки, вентиляционные решётки (прорези)
- шестерни: прямозубые и косозубые (допускается приближение эвольвенты
  полигоном), зубчатые рейки
- шкивы GT2/GT3/T5 под ремень, со ступицей и установочным винтом
- кулачковые муфты Олдэма (3 части = 3 образца с сопряжением)
- подшипниковые узлы: стаканы, прижимные крышки, дистанционные втулки
- шарниры (hinge) с кольцевым зацеплением
- кабель-каналы, зажимы-клипсы (snap-fit с перехлёстом)
- ручки-барашки с насечкой (knurling через циклы)
- импеллеры/крыльчатки (rotate + циклы)
- рамки/безели с фасками переменной глубины

**Ферменные/стержневые (раздел «wire»), для них заполняйте `graph`:**
- плоские фермы Прэтта/Уоррена/Хау с равными панелями
- пространственные башни (4 опоры), переменный шаг раскоса
- рамы квадрокоптеров (X/H), балки двутаврового сечения «труба+полки»
- трубопроводные трассы с отводами под 90°/45° (цепочки `hull()`)
Для wire-образцов: узлы — центры стыков, рёбра — стержни. Узлы пишите в мм,
как они реально стоят в коде.

**Эскизные профили (revolve/extrude — тоже «voxel»):**
- валы ступенчатые с канавками (rotate_extrude замкнутого профиля)
- фланцы с болтовыми окружностями (linear_extrude + полярный цикл)
- ручки с эргономичным профилем сплайном-полигоном

## Язык промптов (важно!)

- Естественные разные формулировки, как живой инженер: «Сделай…», «Нужна
  деталь…», «Спроектируй…», «Хочу напечатать…». БЕЗ единого шаблона.
- Всегда с габаритами в тексте (модель обязана учиться читать размеры из
  текста). В ~20% промптов — допуски («+0.2 на печать», «с зазором 0.15»).
- RU и EN не обязаны быть дословным переводом, но геометрию описывают одну.

## Чего НЕ надо

- Не повторяйте паттерны нашего текущего корпуса: «параллелепипед с полостью»,
  «стакан под подшипник по кругу», «балка-ферма 4-угольная с диагоналями» —
  это у нас уже есть и выучено до нуля лосса.
- Не нужны сферы>§30 сегментов-эстетики, витражи polyhedron на 500 граней,
  органические скульптуры — бесполезно для инженерной модели.
- Не генерируйте картинки/PNG — их сделает наша сторона рендером.

## Объём и сортировка

- Цель: **2 000–3 000 образцов**, ~25–30 семейств.
- Датасет сортируйте по семействам по каталогам; имена файлов
  `part_NNNN.scad` с ведущими нулями.
- Если можете запустить OpenSCAD локально — прогоните `openscad
  --backend=manifold -o out.stl file.scad` и дропайте образцы с ненулевым кодом
  возврата. Не компилируется → не сдавайте.

## Как будем проверять мы (для понимания планки)

1. Статический инвариант: `$fn = 32;`, скобки/строки, без nan/undef.
2. Компиляция manifold → STL: watertight, 1 компонента, χ согласована.
3. Габариты мешей против `expected_bbox_mm`: ≤ 15% по любой оси.
4. Для wire: граф связный, без изолированных узлов, длины рёбер > 0.
5. Хэши SHA-256: правка файла после манифеста = отклонение.

Готовый результат — одним или несколькими коммитами в `optional_data/data/gen2/`.

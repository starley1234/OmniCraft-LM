## A. `sketch1` — 2000 профильных деталей в 20 семействах

Задание: профиль — это **явный массив точек в заголовке файла**, дальше
`polygon(points = …)` и ровно один `linear_extrude(height = H)` **или**
`rotate_extrude(angle = 360)`; никакого `hull` поверх 2D-примитивов, одна
замкнутая ломаная.

| что | значение |
| --- | --- |
| строк | 2000 (`<family>/part_NNNN.scad`, 20 семейств по 100) |
| `manifest.jsonl` sha256 | `95c3ff7457741936f56c13a3d2ac89b62f5321ef2315d2c62e7c623cc53c4175` |
| выдавливание | `linear` 1795, `rotate` 205 |
| точек в профиле | 6 … 40 (все по правилам заявки) |
| профили | средняя площадь 1582 мм², средний периметр 255 мм, все CCW и простые |
| проверка профиль ↔ STL | худшее расхождение объёма 0.64 % (для линейных — площадь × высота, для тел вращения — теорема Паппа) |
| худшее расхождение габарита | 0.0000 % (допуск приёмника 15 %) |
| отброшено на генерации / пропущено дублей | 0 / 449 |
| уникальность промптов | RU 0 дублей, EN 0 дублей |

Семейства: `camdiscs` (кулачковые диски с полярным профилем r(θ)), `leverarms`
(коромысла и коленчатые рычаги по двум-трём бобышкам), `hookplates` (крюки
J-образные, глубокие и с открытым зевом), `eyelugs` (вилки и открытые
C-кольца с хвостовиком), `windowplates` (плиты с окном или keyhole-пазом на
кромке), `pawls` (собачки с треугольным клювом), `eccentrics` (эксцентрики:
яйцо, ступенчатый, диск с двумя лысками), `sprockets` (звёздочки 8–16 зубьев),
`rackbars` (реечные планки с трапециевидными зубьями), `tslots` (сечение
T-паза, один или два настоящих паза), `keybars` (шпонки: призматическая,
сегментная, клиновая, шестигранная), `standoffs` (круглые стойки: шпулька,
с фланцем, ступенчатая, коническая — все с отверстием), `formwashers`
(шайбы: с фаской, с цековкой, сферическая, ступенчатая и C-шайба с открытым
пазом), `pclips` (П-скобы и омега-скобы под трубу), `fanrotors` (сечение
крыльчатки: 7–11 загнутых назад лопаток на ступице), `arcstops` (кольцевые
секторы с упорным выступом), `overslots` (планки с увеличенными окнами под
регулировку), `flatadapters` (адаптерные пластины: double-D, single-D,
шестигранник, со шпоночным пазом), `sinkframes` (П-образные рамки под
радиатор), `guardgrids` (защитные решётки: рёбра на основании между
стойками).

Строка манифеста — обычные ключи плюс `profile` (CCW, ≥ 0) и `extrude`:

```json
{
  "file": "camdiscs/part_0001.scad",
  "family": "camdiscs",
  "prompt_ru": "…",
  "prompt_en": "…",
  "expected_bbox_mm": [38.0, 38.254, 14.0],
  "parameters": {"base_r": 17.0, "boss": 0.0, "lift": 4.0, "points": 26.0, "thickness": 14.0},
  "graph": null,
  "profile": [[38.0, 17.697], [37.539, 21.773], "… 26 точек всего"],
  "extrude": {"kind": "linear", "height_mm": 14.0}
}
```

Заголовок самого файла:

```scad
$fn = 32;

// --- parameters (mm) ---
profile_height = 14;      // extrusion height
profile_points = 26;      // points of the closed outline

profile = [[38, 17.697], …, [37.506, 13.628]];  // single closed polygon, 26 points, counter clockwise

// --- the one profile operation ---
linear_extrude(height = profile_height) polygon(points = profile);
```

`expected_bbox_mm` — измеренный габарит собранного тела (не «задуманный»),
поэтому проверка приёмника на 15 % проходит точными значениями.

## E. Что нашлось и что исправлено по ходу

Это стоит перепроверить в первую очередь — здесь были настоящие ошибки, а не
косметика.

1. **`sketch1`, `eyelugs` (вилка).** При узком зеве и широком основании фаски
   углов щёк выходили за наружную грань, контур самопересекался. Теперь радиус
   фаски ограничен половиной толщины щеки, а сам зев — шириной основания
   (`slot_w ≤ base_w − 12`).
2. **`sketch1`, `formwashers` (`stepped_c`).** Буртик ступенчатой шайбы мог
   оказаться шире основания (2.12 % случаев) — контур вырождался. Буртик
   ограничен `outer_r − 1`.
3. **`sketch1`, `pclips` (омега-скоба).** Контур строился смещением срединной
   линии; у длинных лапок смещение складывалось само на себя. Теперь контур
   строится явно (наружная дуга → лапка → торец → внутренняя дуга → лапка),
   а длина лапки ограничена 0.85 радиуса кольца — эта граница проверена на
   расширенной сетке параметров.
4. **`para1`, подбор формулировок.** Выбор из пула шёл шагом по индексу
   (`(variant + salt·5) mod len`): для пулов из пяти вариантов все «соли»
   вырождались в одну, и на 80 однотипных деталях уникальные перефразировки
   заканчивались (сборка падала на `gen2_bearings_0046`). Теперь выбор идёт по
   смешанной системе счисления (`variant // 5ᵃˡᵗ mod len`) — комбинаций стало
   на порядки больше, 4000 строк собираются без единого отказа.
5. **`para1`, смысл параметров.** «Шаг» подписывался как «шаг резьбы» даже у
   панелей со щелями и шкивов — заменено на нейтральное «шаг»; параметры со
   значением 0 и параметры, просто повторяющие габарит, больше не попадают в
   текст (раньше могло получиться «шаг 0 мм»); неизвестный ключ параметра
   больше не протекает в русский текст латиницей.
6. **Проверка после правок.** Все 20 семейств `sketch1` прогнаны по 500
   индексов (10 000 отрисовок) — страховка `outline is not a simple polygon`
   не сработала ни разу, то есть чинятся причины, а не конкретные индексы.

Отдельно честно: в `asm1` полный прогон аудита в этот раз выполнен **и с
STL-обходом каждой размещённой детали**, и без него — оба дают 0 проблем
(см. `optional_data/data/asm1/GENERATION_REPORT.md`).

## F. Что запустить для проверки

```bash
# 1. статические + геометрические инварианты, все три корпуса
python tools/dataset_sketch1/verify1.py --parts-dir optional_data/data/sketch1
python tools/dataset_asm1/verify2.py --parts-dir optional_data/data/asm1
python tools/dataset_para1/verify_para1.py --parts-dir optional_data/data/para1

# 2. тот же аудит asm1 плюс STL-обход каждой из 4138 деталей (медленно)
python tools/dataset_asm1/verify2.py --parts-dir optional_data/data/asm1 --stl

# 3. контрольные суммы
cd optional_data/data/sketch1 && sha256sum -c SHA256SUMS.txt && cd ../..
cd optional_data/data/asm1    && sha256sum -c SHA256SUMS.txt && cd ../..
cd optional_data/data/para1   && sha256sum -c SHA256SUMS.txt && cd ../..

# 4. выборочный прогон семейств sketch1 (быстро, с STL)
python tools/dataset_sketch1/probe1.py --count 3 --stl

# 5. пересборка (детерминированная: Rng(family, index), seed 20260929)
python tools/dataset_sketch1/build1.py --count 100 --out optional_data/data/sketch1 --report
python tools/dataset_asm1/build2.py   --count 90  --out optional_data/data/asm1   --report
python tools/dataset_para1/build_para1.py --count 800 --out optional_data/data/para1 --report

# 6. ваша сторона: настоящий OpenSCAD
openscad --backend=manifold -o /tmp/out.stl optional_data/data/sketch1/camdiscs/part_0001.scad
openscad --backend=manifold -o /tmp/out.stl optional_data/data/asm1/boltplate/scene_0001.scad
openscad --backend=manifold -o /tmp/out.stl optional_data/data/gen2/bearings/part_0039.scad   # то, на что ссылается para1
```

Ожидаемые числа, если всё сошлось:

| корпус | строк | семейств | проблем |
| --- | ---: | ---: | ---: |
| `sketch1` | 2000 | 20 | 0 |
| `asm1` | 900 | 10 | 0 |
| `para1` | 4000 | 54 | 0 |

## G. Честные ограничения

- Локальная проверка — симуляция приёмника на `manifold3d` + `trimesh`;
  окончательное слово за вашим `openscad --backend=manifold`.
- `sketch1`: габарит в манифесте — измеренный, а не задуманный; расхождение
  профиля и тела вращения считается по теореме Паппа, а не по CAD-ядру.
- `asm1`: детали сопрягаются с зазором 0.25 мм, поэтому «идеальной сборки без
  зазора» в корпусе нет — это сделано специально под требование ≥ 0.2 мм.
- `para1`: промпты — шаблонная композиция с большим числом вариантов
  (регистр × зачин × фичи × концовка × размеры), а не независимые тексты от
  языковой модели; факты при этом всегда из источника.
- `tolerance_ru` добавляет допуски/посадки поверх детали, у которой их никто
  не заказывал: это учебная формулировка, а не требование к конкретной
  геометрии.

## Четыре задачи на выбор (каждая — отдельная сессия)

### D. Абляция aux — почему v9 потерял bbox (первый приоритет)
Симптом: bbox ≤15% 0/42, медиана 1.67 — при нулевом числе ложных промптов в данных.
Первая в истории версия, где aux реально шёл (gt 100%, lambda_geom 0.1; в v8 был ≈0).
- Эксперимент: voxel-лег v9 «с нуля» с `--lambda-geom 0` — готовая последовательность
  команд в разделе «Команды» ниже (шестой аргумент `wsl_train.sh`, добавлен под задачу D).
- **Артефакты v9 сохранены** (до запуска абляции rollback затрёт `checkpoints/voxel`):
  веса — `~/omnicraft/v9_backup/{voxel_v9,wire_v9}` в WSL и зеркало в Windows
  `checkpoints/`; eval-отчёты — `runs/train_v9/eval_{voxel,wire}.jsonl`.
- Вернулось к v8 → виноват aux: играть с lambda/расписанием (при lm 0.03 vs aux 0.28
  градиенты сопоставимы). Не вернулось → разбирать поставки №5–7 (код/стили, а не промпты).

### A. Геометрия wire (наибольший выигрыш, самая большая работа)
Проблема: в слое всего **30 скелетов кода**, 2 801 обучающий образец. Модель видела
почти одну форму, поэтому 29% компиляции и габарит мимо в ~2 раза.
Нужны новые генераторы (не перефразировки существующих): фермы с разной схемой
раскосов, плоские и пространственные рамы, мачты, кронштейны из прутка, стойки.
- Куда класть: `src/data/generators/` рядом с `wire_truss_gen.py`.
- Проверка разнообразия: `python tools/analyze_corpus.py <файл> --layer wire`
  (целевой ориентир: «строк на скелет» < 20, доля топ-скелета < 10%).
- Дальше: `omni validate` → `tools/build_corpus_v8.py` → `omni split` → чейн.

### B. Scale-инъекция для запросов без размеров
Симптом: `conv` даёт 3/6 по компиляции, но **0/6 по габариту** — когда размеров нет в
тексте, модель не берёт их из `[SPECS]`. Это ровно то, ради чего существует хук слоя 12.
- Эксперимент: один и тот же conv-промпт с разными bbox в `[SPECS]`; если габарит
  результата не меняется, вклад хука близок к нулю и чинить надо его, а не данные.
- Код: `src/runtime/specs_hook.py`, `src/model/hook_manager.py` (инъекция только на
  prefill), `src/model/latent_bridge.py` (ScaleMLP).

### C. Дешёвый прирост compile rate
7 из 12 провалов voxel — «top level object is empty»: модель объявляет модули и забывает
верхнеуровневый вызов. Варианты: страж в валидаторе корпуса (все обучающие коды обязаны
иметь вызов верхнего уровня) и/или линтер-починка в `tools/evaluate_generation.py`.
Второй класс — псевдо-OpenSCAD (`function` с телом модуля, `union` как инфиксный
оператор), лечится только данными.

## Грабли, на которые уже наступили (не наступать снова)
1. **`lm=0.0000` — не сходимость**, а шаг, где OOM съел все чанки. Сторож `[EMPTY STEP]`
   теперь кричит, 20 подряд = падение. Если увидели — снижайте `--max-tokens-per-forward`.
2. **Бюджет = порог отсева.** Образец длиннее бюджета неделим и всегда уходит в OOM;
   трейнер отсеивает такие заранее и печатает сколько. Потолок машины: 1000–1200 токенов
   (при 1600 падают даже чанки 8×96, при `--max-vram-gb 15.3` падает драйвер).
3. **`echo "$(date) rc=$?"` всегда печатает 0** — подстановка затирает `$?`. Снимать rc
   в переменную сразу (в чейне v8 уже так).
4. **Бюджет eval должен быть ≥ p95 длины кода** (сейчас 1024). 384 токена давали ложные
   провалы, а слишком малый бюджет маскирует зацикливание недоученной модели.
5. **Промпты-пустышки отравляют корпус.** Фраза, отвечающая многим геометриям («деталь
   NxNxN мм»), учит игнорировать текст. Фильтр — в `tools/build_corpus_v8.py`, вердикт
   пишется в `metadata.quality` каждой строки (перепроверять корпус не нужно).
6. **Демо держит VRAM.** Перед обучением — кнопка «выгрузить модель» в UI или
   `POST /api/model {"action":"unload"}`; полностью память отдаёт только выход процесса.
7. **Чекпойнты не защищены от чужого локального train.** 2026-10-02: внешний
   `train_spatial --layer voxel` с дефолтным конфигом за ~40 с затёр Windows-копию
   чекпойнта v9 (step 0, `data\processed\splits\train.jsonl`). Перед любым запуском —
   `omni status`; восстановление: `rsync -a --checksum` из WSL.

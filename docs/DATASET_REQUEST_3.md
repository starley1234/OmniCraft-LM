# Заявка №3 на генерацию датасета (для внешнего агента)

> Статус входа: gen2 (2240) и gen3 (2600) приняты нашим настоящим OpenSCAD
> 100/100 после ваших правок. Правила безопасности геометрии из
> `DATASET_REQUEST.md` действуют без изменений (перекрытия ≥ 0.2 мм,
> `$fn = 32;`, самодостаточность, ≤ 12 КБ). Ниже — три новых блока под
> следующие фазы архитектуры. Каталоги: `optional_data/data/sketch1/`,
> `optional_data/data/asm1/`, `optional_data/data/para1/`.

## Блок A. Эскизный корпус `sketch1/` — с ground-truth профилем

Нужен для SketchCanvas (2D-холст): детали, где суть — плоский замкнутый
профиль, выдавленный или завёрнутый. **1600–2400 образцов**, 20 семейств:
кулачки, рычаги, крюки, проушины, пластины с фигурными окнами/карманами,
собачки, эксцентрики, звёздочки под цепь, рейки, направляющие с Т-пазом,
шпонки и призмы, профильные распорки, фасонные шайбы, скобы П и Ω, крыльчатки
в сечении, сегменты-стопоры, планки с оверсайз-окнами, лыски-адаптеры,
рамки под радиатор, решётки-щитки.

Формат кода: профиль задаётся через `polygon(points=[...])` (точки — явный
массив переменных в шапке) + ровно один из: `linear_extrude(height=H)` /
`rotate_extrude(angle=360)`. Без hull по 2D-примитивам — профиль должен быть
ОДНИМ полигоном (мы учим канвас предсказывать точки).

Строка manifest.jsonl — прежний формат + два новых поля:

```json
{
  "file": "cams/part_0001.scad", "family": "cams",
  "prompt_ru": "...", "prompt_en": "...", "expected_bbox_mm": [.."],
  "parameters": {...}, "graph": null,
  "profile": [[x1,y1],[x2,y2],...],          // точки polygon(), мм, по порядку обхода CCW
  "extrude": {"kind": "linear", "height_mm": 12.0}
}
```
или `"extrude": {"kind": "rotate", "axis": "z"}`. Правила: полигон простой
(без самопересечений), CCW-обход, 6–40 точек, coord ≥ 0. Аудит соберёт
из `profile` площадь/периметр и сверит с STL.

## Блок Б. Сборочный корпус `asm1/` — деревья SE(3)

Для AssemblyCanvas (следующая фаза): **800–1200 сцен** из 2–6 деталей.
Каждая деталь — свой `module`, сцена — вызовы с явными `translate`/`rotate`.
Никаких пересечений деталей (шахматный зазор ≥ 0.2 мм). Примеры сцен:
винт+пластина+гайка; вал+2 подшипника+стакан; кронштейн+2 болта+шайба;
фланец+прокладка+крышка; рама+4 стойки; шкив+ремень(изогнутая лента)+наклон.

Кодовая дисциплина: детали в `modules/` сцены недопустимы — весь .scad в
одном файле; каждый узел сцены вызывается из `assembly()` с явным переводом.

manifest: к каждой строке поле
```json
"assembly": [
  {"module": "plate", "t": [0,0,0], "q": [0,0,0,1]},
  {"module": "bolt",  "t": [12,12,10], "q": [0,0,0,1]}
]
```
(`t` — мм, `q` — кватернион w-last (x,y,z,w)). TuneUp: ±повороты кратно 90°
или 45° — сеточные, не произвольные углы (первичная дисциплина сборки).

## Блок В. Парафразный блок `para1/` — почти бесплатная диверсификация языка

Для 800 случайных образцов из gen2+gen3 (выберите равномерно по семействам):
тот же код, **пять новых формулировок** промпта в разных регистрах:
1) формально-инженерная; 2) цеховой сленг («надо бы уголок на 40ку…»);
3) краткая в стиле чата; 4) с допусками/единицами; 5) англоязычная техническая.
manifest-строка: `{"source_id": "gen2_zbrackets_0042", "family": ...,
"prompt_ru": "...", "prompt_en": "...", "expected_bbox_mm": [...]}` и
`"code_ref": "gen2/zbrackets/part_0042.scad"` (сам код не дублируйте —
подтянем по ссылке). 800×5 = 4000 строк.

## Планка и сдача

Прежняя: `verify_*.py` 0 проблем, SHA256SUMS, RU+EN уникальны, сцены/графы
целостны. Новая ветка, пуш, фраза. Наша сторона: настоящий OpenSCAD по всем
трём блокам + аудит профилей/трансформаций (включая проверку непересечения
деталей в asm1 — сделаем через перманентный STL каждого узла и попарный
overlap-тест).

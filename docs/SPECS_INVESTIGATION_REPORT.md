## 1. Диагноз: ПОДТВЕРЖДЁН — и расширен двумя пунктами

Все три дефекта из §0 постановки воспроизведены точно, без модели — запуском
`extract_specs_from_text` на промптах пробника (`report.md`/`cases.jsonl` сходятся бит-в-бит):

| Утверждение из постановки | Вердикт | Подтверждение |
|---|---|---|
| `class: freeform` — OOD-значение | **подтверждено** | строка `object_class="freeform"` была зашита в минер жёстко (бывш. `specs_hook.py:145-146`); словарь обучения — `metadata.origin`, 140 семейств в манифестве + fallback-слой, `freeform` отсутствует |
| bbox 100³ при «Ø96, толщиной 10» | **подтверждено** | `_DIMS_RE` понимал только `AxBxC`; на «реальных» промптах held-out eval минер давал верный bbox лишь **5/36** (остальные — заглушка) |
| topology от sketch при canvas=voxel | **подтверждено** | при промпте без слов-подсказок `mined.canvas=sketch` → `topology=closed profile + extrude/revolve`, а рантайм переключает canvas на voxel; в блоке — противоречие. `plate_mined` (`module body() extrude()`) — прямое следствие |
| «слепое доверие» блоку | **подтверждено** | `flange_wrongspec` 200³ → деталь 209×300; при этом `flange_nospecs` (верный масштаб холсту, без блока) даёт верные XY 96 — канал масштаба работает, вина не в холсте, а в мусорных числах |

**Расширение 1 — eval был заражён тем же багом.** `tools/evaluate_generation.py`
составлял блок тем же минером: `class: freeform` (42/42!) и `topology` от
минер-канваса; bbox на eval подставлялся истинный (`expected_bbox_mm`) — поэтому
bbox-метрики v8/v9 измерялись на модели, которой в промпте лгали про *тип детали*.
Вывод «voxel bbox ≤15% = 0/42 у v9» частично промеряет не модель, а этот стык.
Новые базы eval следует снимать после фикса минера (§5, экспемент E1).

**Расширение 2 — часть «непобедимого» bbox-проигрыша живёт в данных.** На срезе
140 превью (задача B) найдены строки, где промпт противоречит геометрии/габариту:
`para1`-перефразировки с размерами из чужой детали (`lbrackets`, `threads`,
`threadcaps`) и импорты `parts_import`, где код не повторяет заявленные фичи
(`airducts`, `handles`, `leverarms`, `bearings`, `flanges`, `voidplates`).
Даже идеальный блок не научит модель уважать текст, если ⅓ корпуса учит, что
текст и геометрия не связаны. Вердикты: `data/previews/families_v9/verdict_template.csv`.

## 2. Ответы на вопросы постановки

**Достаточно ли починить минер, или обязательно переобучение?**
Чинить минер — обязательно и достаточно для *всех промптов, где размеры есть в тексте*
(это основной класс жалоб: Ø96 → 100³ не повторится). Переобучение нужно для двух
остатков: (a) conv-промпты без размеров вообще — блок обязан честно получать дефолт,
а модель обязана тогда опираться на prior семейства, а не на 100³-куб (сейчас этому
её никто не учил); (b) устойчивость к «серому» блоку (частично разобранный минер).
Это стратегия **D (гибрид)**: A сейчас, C — следующим прогоном.

**Должен ли `[SPECS]` участвовать в форме или только в масштабе?**
Участвует фактически, и это заложено в обучение: `class` = имя семейства — conditioning
по форме (эксперимент `flange_oracle` vs `flange_abc`: с `class=flange` модель выдала
цилиндрический фланец, с `class=freeform` — плиту, при том же bbox). Значит блок —
не «только масштаб», а **сжатое описание задачи**; требование к нему одно: быть чистой
функцией промпта, той же, что `compose_specs` строил из записей корпуса. Отключать
блок на инференсе нельзя — hartayl №2: `<|spatial_*|>` без блока не гарантирован.

**Что делать, когда минер не уверен?**
Никаких правдоподобных заглушек вместо честного незнания: значения берутся только из
текста; ничего не найдено → документированный дефолт [100,100,100] + `WARNING` +
`provenance` с пометкой `bbox:default` (новое поле, в блок не рендерится, видно в
API/JSON). Второй проход парсером — избыточен: детерминированный автомат покрывает
все форматы корпусных шаблонов; LLM-парсер ломает детерминизм инференса (hartayl №3).
Единственная допустимая «домысленная» величина — z-приор 0.45·Ø для круглых деталей без
заявленной высоты (медиана z/D по 28 круглым voxel-семействам манифеста; см. код).

**Нужен ли `topology` в блоке?**
При текущем обучении это константа слоя — ноль информации, но и ноль вреда, если он
канонический. Вред он приносил только противоречием canvas. Оставлен в блоке
(контракт ARCHITECTURE §8.1, переобученные веса его ждут), теперь всегда
`_default_topology(итоговый canvas)`. Удалять строку без дообучения нельзя —
сдвиг последовательности токенов.

## 3. Патч (применён)

**`src/runtime/specs_hook.py`** — переписан минер, контракт (`render/parse/compose`)
не изменён:

1. **bbox** — `_mine_bbox` по приоритету: `AxBxC` (разделители `x/х/×/на/by`) →
   `ØA×B` → «кубик N мм» → шестигранник «между гранями S» (bbox = `2/√3·S × S × H`,
   конвенция корпуса) → **круг**: Ø/diameter/«N mm OD/across/outer diameter»/«квадрат N»,
   с поиском *высоты* обоих порядков («толщиной 10», «10 мм толщиной», «10 mm thick»)
   и z-приором при её отсутствии → **пара + высота** («80 на 50 мм, толщина 4»);
   «длина/пролёт» линейных деталей ставится в X, «высота/толщина» остаётся в Z;
   пара после слов «габарит/envelope/в плане» приоритетнее случайных отверстийных Ø;
   контекстная защита: Ø сразу после «отверстие/проход/bore/паз» и перед
   «по окружности/bolt circle/под винт» — не энвелоп. Окно правдоподобия
   0.5–1000 мм, всё вне — fallback с предупреждением. Исключений не бросает ни один путь.
2. **class** — `_CLASS_HINTS`: 30 правил «ключевое слово → настоящее имя семейства
   из словаря корпуса» (фланц→`flanges`, втулк→`spacers`, кронштейн→`lbrackets`,
   ферм→`trusses`, монтажная плита→`mounting_plate_bracket/chamfered_plate`, …);
   нет совпадения → имя canvas-слоя — ровно fallback трейнера
   (`metadata.get("origin", layer)`), т.е. значение из распределения обучения.
   Тест проверяет все цели маппинга и class'ы на 140 манифестных промптах против
   манифеста семейств — «за словарь не выходить» загардовано.
3. **topology/canvas** — новый аргумент `extract_specs_from_text(text, canvas_hint=…)`;
   все четыре вызывающих рантайма (demo_server, evaluate_generation, specs_probe,
   bench_generate) передают итоговый слой, топология считается от него.
4. **provenance** — непустое поле `Specs` для логов/UI/датасет-аудита, в блок не рендерится.
5. `_CANVAS_KEYWORDS` дополнен (плита/крышка/хомут/короб/перфорация→voxel,
   проушина/ласточкин/звёздочка→sketch, вышка→wire) — только при отсутствии hint.

**`tools/demo_server.py`** — единый mined- Specs (плюс устранена двойная `[/SPECS]`
в API-ответе, §2¹ постановки; в `result` добавлен `specs_provenance`).
**`tools/evaluate_generation.py`** — `canvas_hint=args.layer` (eval меряет production-путь).
**`tools/specs_probe.py`** — `mined`-режим повторяет новый рантайм; ручной `specs`-режим не тронут.
**`tests/test_specs_hook.py`** — +13 тестов: акцептационный промпт фланца, 6 формулировок
Ø-промптов, пара+толщина, пролёт/сечение, куб/шестигранник/standoff, «отверстие не
становится энвелопом», честный дефолт, непротиворечие topology, словарный class и
регрессионная планка «≥120/140 ≤15%» на манифестном срезе, «не падает на мусоре».

**Метрики минера (тот же харнесс, до → после):**

| набор | ≤15% | ≤60% | хуже |
|---|---|---|---|
| 140 манифестных промптов | 89 → **130** | 92 → 132 | 48 → 8 |
| 36 eval-промптов с GT | 5 → **29** | 5 → 31 | 31 → 5 |

Оставшиеся 8/5 — не баги парсера: составные высоты (flange+ступица, корпус+стойки,
патрубок), выводные размеры (Ø шкива из делительного), 3 строки с испорченным промптом
и 1 строка без размеров в тексте (standard_part). Для них блок по определению может
дать только честный дефолт — см. стратегию C.

## 4. Почему не выбраны чистые A/B/C

- **Чистое B** («не давать блоку перекрывать текст») нереализуемо без обучения:
  приоритет блока — выученное поведение (conv-стили нарочно без размеров). Единственный
  нетренировочный способ «понизить блок» — не давать его вовсе, ломает hartayl №2 и
  лишает hook-канал масштаба. Взят его слабый вариант: блок = чистая функция текста.
- **Чистое A** не лечит промпты без размеров и не даёт устойчивости к ошибкам минера
  на редких формулировках.
- **Чистое C** (переобучение на «шуме») дорого и не отменяет того, что инференс-минер
  был просто сломан: после дообучения на мусорных блоках мусор станет нормой, и
  детерминированный парсер так и не появится.

## 5. План экспериментов (для владельца, в WSL с весами; порядок — строгий)

**E0. Статическая приёмка патча (сделано частично).**
`python tools/omni.py preflight --with-tests`. В песочнице агента прогнано: 16/16
тестов `test_specs_hook.py`, 43 passed / 3 skipped (openscad-скипы) остального
не-torch-набора; torch-тесты и полный preflight здесь непроходимы (нет torch/OpenSCAD).
Зелёный preflight на машине владельца — обязательное условие дальнейших прогонов.

**E1. Переснять пробник (без обучения; ~15 мин GPU).**
```
python tools/specs_probe.py --out optional_data/specs_probe_v2 --max-new-tokens 1024
```
Критерии приёмки (из §10 постановки): `flange_mined` компилируется; bbox в ≤15% от
[96,96,10] (до: 11.4); в коде присутствуют d=96, bore d=32 и цикл из 5 отверстий d=6
на Ø70; `plate_mined` компилируется (0 parser-ошибок класса `extrude()`); `cap_mined`
≠ 100³. Если bbox-приёмка не прошла полностью — не чинить минер «под промпт», а
перейти к E3 (поведение модели, не парсера).

**E2. Снять новую базу eval на исправленном харнессе (v9/v11 чекпойнты, ~10 мин/слой).**
```
bash tools/wsl_eval.sh voxel     # тот же held-out 42
```
Ожидание: class теперь in-vocabulary → compile-доля не ниже прежней (≥48%), bbox ≤15%
заметно лучше 0/42 (у v8 с «правильным bbox + freeform» было 16/42 — теперь и тип верный).
Все будущие сравнения — только против этой базы; старые цифры v8–v11 помечены в
TRAINING_LEDGER как снятые с OOD-блоком.

**E3. Дообучение C: «серые [SPECS]» (v12-leg, ~2.5 ч, тот же бюджет 2900×16@1000).**
Меняется только `trainer.build_sequence` (augmentation на лету, без нового корпуса):
1. ~60% шагов: блок как сейчас (истинный, GT);
2. ~30%: блок = `extract_specs_from_text(prompt_данной_строки)` — т.е. реальный вывод
   минера на формулировках корпуса (сагласованный по построению, учит модель читать
   серые, но правдивые блоки и даёт минёру «доказательство» на 60k промптов);
3. ~10%: деградированный блок — bbox→100³, class→имя слоя, текст без размеров:
   код и метка не меняются → модель учится, что при `bbox:default` масштаб берётся
   из формулировки/prior семейства, а не из заглушки.
   Контроль регресса: aux λ=0.1 как v9/v11 (абляция v10 доказала его невиновность).
Критерии приёмки: held-out voxel ≥ 24/42 compile и bbox ≤15% ≥ 16/42 (не хуже v8 на
честном блоке); conv-подмножество ≥ 4/6 bbox-попаданий (сейчас 2/6); «no top-level»
и parser-классы не растут. Побочный эффект: E3 фиксирует и инференс-аугмент — при
полностью безразмерном запросе модель генерит prior-форму (кубик-кронштейн допустим),
а не куб 100³ с дырками.

**E4. Санитария корпуса (параллельно, без GPU).**
- применить вердикты B-аудита: `filter_corpus_by_verdict.py` — **но** для `airducts`,
  `handles`, `leverarms`, `bearings`, `flanges`, `voidplates` чистить всё семейство
  `src=parts_import` (в манифесте по одной выборке, а генератор один: битые фичи
  системны), а `para1`-строки чистить промптом «текст↔bbox»: пересчитать сверку
  `build_corpus_v8.py` тем же `_mine_bbox` (он теперь видит `AxB`, `на`, `by`, Ø
  и «envelope A x B x C» — фильтр прежним `_DIMS_RE` эти форматы пропускал;
  на новом минере расхождение >15% дают ровно 9 строк из 140-среза).
- переопределить «допустимые» расхождения для составных деталей: bbox включает
  ступицы/стойки, которых нет в размерной фразе — не bad, а note.

**E5. Косметика-страж:** тест на «блок не содержит double `[/SPECS]`» уже закрыт
удалением `+ STOP_TOKEN`; дополнительно — `parse_specs_block` в рантайме обязан
оставлять provenance="block" (проверено).

## 6. Риски тех же дефектов у других семейств (для §7.5 постановки)

Промпты, где габарит задан Ø-парой/двумя числами + толщиной — все импортированные
`ext_domain`/`gen2/gen3` семейства (flanges, caps, spacers, boltcircles, airducts,
cleats…). На 140-срезовом манифесте «до» падали в 100³ **48** семейств; «после» —
8, из них 3 — мусор в самих данных (см. E4), 5 — составные/выводные размеры.
Визуальный контроль: `render_family_previews.py --per-family 3 --families <flanges,caps,spacers,...>`
после чистки; вердикты по формату уже принимаются фильтром.

## 7. Что здесь не проверялось (честно)

- Реальные генерации после патча (нет весов) — E1/E2 на машине владельца.
- Доля «0 строк с ложным габаритом» по всему корпусу — старая сверка сделана
  прежним парсером, который не видел форматы `AxB+толщина`/`Ø`/`by`; пересчёт — E4.
- 141-е значение class-словаря (140 семейств манифеста +, вероятно, fallback слоя):
  предположение подтверждается косвенно (m.get("origin", layer) в трейнере); точная
  проверка — `jq -r '.metadata.origin' combined_v9_fixed.jsonl | sort -u | wc -l`.

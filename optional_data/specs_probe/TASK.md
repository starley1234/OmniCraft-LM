# Постановка: расследование механизма `[SPECS]` (Geometric CoT)

**Кому:** внешней модели/агенту с vision и большим бюджетом токенов.
**Инструменты адресата:** нет OpenSCAD, нет обученной модели, нет GPU. Есть этот файл,
код репозитория, данные и набор картинок с прогонов обученной модели.
**Что требуется вернуть:** разбор ситуации + план исправления + план экспериментов
с критериями приёмки. Патчи и запуски выполнит владелец репозитория по вашему плану.

---

## 0. TL;DR (наша рабочая версия — проверьте или опровергните)

Блок `[SPECS]` не «портит всё» сам по себе: модель **обучена** брать масштаб из него
(conversational-стили промптов нарочно без размеров). Проблема в том, что **на инференсе
`[SPECS]` собирается из эвристического парсера `extract_specs_from_text`, который выдаёт
не то, что модель видела при обучении**, а именно:

1. `class: freeform` — такого значения **не было ни в одной из 75 157 обучающих строк**;
   в обучении `class` = `metadata.origin` (имя семейства: `flange`, `lbrackets`, `threads`, …).
2. `bbox: [100, 100, 100]` — дефолтная заглушка, потому что минер понимает только `AxBxC`,
   а «диаметром 96 мм, толщиной 10 мм» — нет. Для запроса пользователя правильный bbox `[96,96,10]`.
3. `topology` противоречит `canvas`: для промпта без слова-подсказки miner ставит
   `topology: closed profile + extrude/revolve` (sketch), но `canvas` рантайм переопределяет
   на `voxel`. В обучении `topology` всегда канонический для слоя (`voxel → csg union/difference`).

Модель **слепо доверяет** блоку: эксперимент с заведомо неверным `bbox [200,200,20]`
сдвигает деталь к 200/300, игнорируя текст «96 мм». Поэтому неверный `[SPECS]`
превращает чёткий запрос в куб 100³.

**Ключевой вопрос для адресата:** что правильнее — (A) чинить минер, (B) не давать блоку
перекрывать текст, (C) переобучить модель на зашумлённых/дефолтных `[SPECS]`, (D) гибрид?
Выбор обосновать кодом + доказательствами ниже.

## 1. Система в 10 строк

Qwen3.5-2B (локально, read-only) учится писать OpenSCAD по текстовому описанию. К слою 12
подключён «пространственный холст» (Canvas): хук на prefill инжектит вектор геометрии,
в т.ч. масштаб из `log(bbox)`. На инференсе генерация двухфазная:
`текст промпта + [SPECS] + <|spatial_voxel|>` → хук слоя 12 → код OpenSCAD.
Проверка кода — настоящим OpenSCAD (`--backend=manifold`). Железные инварианты — `AGENTS.md`.

## 2. Симптом (воспроизведение)

Промпт (встроенный пример демо, `tools/demo_server.py`, `EXAMPLES`):

> Создай круглый фланец внешним диаметром 96 мм, толщиной 10 мм, с центральным
> отверстием 32 мм и 5 отверстиями 6 мм по окружности 70 мм.

Правильная деталь: цилиндр Ø96×10, сквозное отверстие Ø32, 5 отверстий Ø6 на
делительной окружности Ø70.

Фактический `[SPECS]` и результат (демо-сервер, порт 8035):

```
[SPECS]
class: freeform
bbox: [100, 100, 100]
topology: csg union/difference
canvas: voxel
[/SPECS]
[/SPECS]                       <-- двойной закрывающий тег; см. сноску ¹

$fn = 32;
// Freeform cube: 100 x 100 x 100
...
base_len = 100; base_w = 100; base_h = 100;
...
```

¹ `tools/demo_server.py:172` формирует `specs_text = specs.render() + STOP_TOKEN`, а
`render()` уже заканчивается `[/SPECS]` — отсюда дубль в UI. Косметика, но показывает
небрежность стыка. Артефакт кода: `optional_data/specs_probe/flange_mined.scad` (идентичен вашему).

### Доказательная база: 8 прогонов одной модели (voxel, greedy, ≤1024 токена)

Файлы: `optional_data/specs_probe/` — `cases.jsonl` (полные записи), `report.md`, `overview.png`,
`<case>.scad`, `png/<case>.png`. Обзор всех восьми — `optional_data/specs_probe/overview.png`.

| случай | режим | class в блоке | bbox в блоке | ожид. | факт. bbox | max отн. ошибка | compile |
|---|---|---|---|---|---|---|---|
| `flange_nospecs` | без `[SPECS]`, масштаб холсту задан верно | — | — | 96,96,10 | 96, 96, **63.3** | 5.33 | да |
| `flange_mined` | текущий рантайм | freeform | 100,100,100 | 96,96,10 | 100,100,**124** | 11.4 | да |
| `flange_abc` | габарит записан как `96x96x10` | freeform | 96,96,10 | 96,96,10 | 96,96,**26.4** | 1.64 | да |
| `flange_oracle` | правильный блок вручную | flange | 96,96,10 | 96,96,10 | 96,**143**,**21** | 1.1 | да |
| `flange_wrongspec` | заведомо неверный блок | flange | 200,200,20 | 96,96,10 | **209,300**,10 | 2.125 | да |
| `cap_mined` | второй «диаметр»-промпт | freeform | 100,100,100 | 120,120,8 | **169,100.8,142.8** | 16.85 | да |
| `plate_mined` | габарит вида `AxBxC` | freeform | 120,80,8 | 120,80,8 | — | — | **нет (parser)** |
| `bracket_mined` | размеров нет вовсе | freeform | 100,100,100 | — | 100,198,100 | — | да |

Выводы, которые видны невооружённым глазом:
- `flange_mined` — это и есть жалоба: масштаб 100³ из заглушки.
- `flange_oracle` (class `flange`) — уже **узнаваемый цилиндрический фланец Ø96**, а не куб:
  значение `class` реально управляет формой. Ошибка формы остаётся, но тип детали верный.
- `flange_abc` — диаметр 96 в XY верный, но это по-прежнему «Freeform cube»: одного bbox мало,
  class `freeform` тянет в generic-плиту.
- `flange_wrongspec` — деталь **поехала за неверным блоком**, а не за текстом.
- `plate_mined` — при **правильном** bbox не компилируется: сгенерирован псевдо-OpenSCAD
  (`module base_profile() path { … }`, `module body() extrude() { … }`) — класс ошибок
  «sketch-синтаксис на voxel-холсте». Это следствие противоречивого `topology` (см. §4).

## 3. Контракт `[SPECS]` (действующая выжимка)

`ARCHITECTURE.md §8.1`, код `src/runtime/specs_hook.py`:

```
[SPECS]
class: {object_class}
bbox: [{x}, {y}, {z}]      # мм, значения ≤0 → 10.0
topology: {краткая стратегия}
canvas: {sketch|voxel|wire|brep|assembly}
[/SPECS]
```

Гартрейлы: (1) хук без больших полносвязных слоёв; (2) `<|spatial_*|>` не генерируется
без предшествующего `[SPECS]`; (3) генерация детерминированная (greedy / T ≤ 0.2).

## 4.Train vs inference: где расходится распределение

| поле блока | **Обучение** (`src/training/trainer.py:build_sequence`, стр. 270–301) | **Инференс** (`tools/demo_server.py:_generate`, `evaluate_generation.py`, `bench_generate.py`) |
|---|---|---|
| `class` | `metadata.origin` или `layer` — 141 значение, напр. `lbrackets`, `threads`, `flange`, `adapter_flange/conical_reducer`; **`freeform` отсутствует** (проверено по всем 75 157 строкам) | **жёстко `"freeform"`** (`src/runtime/specs_hook.py:145-146`) |
| `bbox` | `verification.target_bbox` — **истинный**, доверенный | минер `_DIMS_RE` (только `AxBxC`), иначе `DEFAULT_BBOX=[100,100,100]` + `WARNING` |
| `canvas` | слой обучения | UI-хинт/эвристика (`voxel`) |
| `topology` | всегда `_default_topology(canvas)` (voxel → `csg union/difference`) | `mined.topology` — считается от `mined.canvas` (для промпта без слов-подсказок = sketch → `closed profile + extrude/revolve`) |

**Итог:** несоответствие по трём полям из четырёх. Модель видела только «правильные» блоки,
поэтому не умеет распознавать мусорный и не имеет обучения «игнорировать блок, если он
противоречит тексту». Усугубляется тем, что `prompt_augment.py` (docstring) *специально*
делает conversational-промпты без размеров: «scale must come from `[SPECS]`». То есть
поведение «взять масштаб из блока» — выученное и ожидаемое; плох именно блок.

## 5. Эксперимент «слепое доверие» (уже проведён)

`flange_wrongspec`: тот же текст, но `bbox [200,200,20]` → факт `[209,300,10]`, ошибка 2.125×.
Сравните с `flange_nospecs` (без блока, масштаб холсту дан верно): `[96,96,63.3]` — XY
попал в 96. Значит:
- текст «96 мм» доходит до холста через `Scale MLP` (канал масштаба работает);
- но когда в промпте есть блок, модель следует **блоку**, а не тексту.

## 6. Гипотезы (ранжированы; проверьте)

- **H1 (главная, подтверждена фактами).** Минера `bbox` + OOD `class` + противоречивый
  `topology` — три независимых дефекта инференса. Исправление минера и `class`/`topology`
  поднимет качество без переобучения.
- **H2.** Даже с правильным блоком модель генерирует фланец лишь приблизительно
  (`flange_oracle` err 1.1) — значит способность к точной геометрии ограничена, и одним
  блоком не лечится. Нужна проверка «правильный блок + больше примеров семейства в корпусе».
- **H3.** `topology` в блоке — вредный лишний сигнал (в обучении он не варьировался).
  Кандидат: убрать `topology` из инференс-блока или всегда ставить `_default_topology(canvas)`.
- **H4.** `class=freeform` — катастрофический токен: проверка `flange_oracle` vs `flange_abc`
  намекает, что class управляет типом детали сильнее bbox. Проверить: `class=flange` +
  `bbox=100³` vs `class=freeform` + `bbox=96,96,10`.
- **H5.** Возможно, стоит подавать блок только когда минер уверен, иначе — «честный»
  `class`/`bbox` из отдельного парсера (правила/небольшая LLM), а не заглушку.

Из `AGENTS.md`:
1. Каждый `.scad` начинается со строки `$fn = 32;`; mock-валидация ≠ CAD-валидация;
   в обучение идут только `*.accepted.jsonl`.

3. Хук слоя 12 срабатывает только на prefill; на KV-кэш-шагах — без изменений.
4. Никаких Triton / static KV cache; CUDA=bf16, CPU=f32.
5. Авторитет гиперпараметров — CLI-флаги `tools/train_spatial.py`; `configs/*.yaml` не читаются кодом.
6. Детерминизм инференса (greedy / T ≤ 0.2); `<|spatial_*|>` без `[SPECS]` не гарантируется.

Ограничение среды: **нельзя запускать обучение/eval, пока идёт чужой прогон**; инференс
делит GPU с WSL. Патчи принимаются только через `python tools/omni.py preflight --with-tests`.

## 10. Критерии приёмки исправления (предложите/уточните)

1. На промпте про фланец итоговый bbox в пределах **≤15%** от `[96,96,10]` и в коде есть
   цилиндр `d=96`, отверстие `d=32`, **5 отверстий `d=6` на БК Ø70**.
2. Для ≥5 разных формулировок («диаметром N», «N мм в диаметре», `AxBxC`) минер даёт
   корректный `bbox` и `class` не выходит за словарь обучения.
3. `canvas: voxel` ⇒ `topology` канонический для voxel (или поле убрано) — `plate_mined`
   перестаёт падать с parser error.
4. `preflight --with-tests` зелёный; добавлены тесты на минер (диаметр/толщина/мусорный ввод).
5. Ни одного `[EMPTY STEP]`/регресса в held-out eval относительно базы; метрика bbox не хуже.
